核心考点速记

表 R6.a 第6章核心考点一览
考点速记要点
C/S 模型客户主动请求、服务器被动响应；客户间不直接通信；可扩展性差（受服务器性能与带宽制约）
P2P 模型节点兼具客户/服务器角色，对等方直接通信；可扩展性好、健壮性强；占用本机资源多，ISP 限制
DNS 基础域名→IP；客户/服务器模型；运行在 UDP 之上，端口 53；层次域名空间：顶级域/二级域/三级域
四类域名服务器根（13 个，指路不代跑）、顶级、权限（每区建议至少两个）、本地（主机查询首先发给它）
DNS 解析主机→本地必为递归；本地→根/顶级/权限常为迭代（"你告诉我该找谁"）；高速缓存 + TTL
FTP基于 TCP 的有状态协议；控制连接 21（整个会话保持打开，传命令）；数据连接 20（按需建立，传文件）
FTP 两种模式主动 PORT：服务器用 20 主动连客户端；被动 PASV：服务器随机开端口等客户端来连；由客户端决定
邮件组成用户代理 + 邮件服务器 + 协议；邮件服务器双重角色（发信时为客户、收信时为服务器）
SMTP推（Push）、TCP 25；三阶段：建立/传送/释放；仅传 7 位 ASCII；不使用中间邮件服务器中转
POP3 / IMAP拉（Pull）、TCP 110；下载并保留 / 下载并删除；IMAP 更强：在线操作、选择性获取部分内容
MIME不取代 SMTP，只做扩展：把非 ASCII 数据编码为 ASCII 再交 SMTP 传输
HTTP 特点基于 TCP（80）可靠传输，但自身无连接、无状态；Cookie（识别码 + 数据库）弥补无状态
持久/非持久连接HTTP/1.0 非持久：每对象 2RTT；HTTP/1.1 持久（默认）：非流水线/流水线（全连续仅 1RTT）
HTTP 报文开始行（请求行/状态行）+ 首部行 + 空行 + 实体主体；方法 GET/HEAD/POST/PUT/DELETE/CONNECT
代理服务器= Web 高速缓存；过期副本用 If-Modified-Since 询问，未改则回 304 不含实体主体

易错清单

⚠️ 高频易错点
  • HTTP 本身是无连接的——虽基于 TCP，但无须先建立"HTTP 连接"。
  • FTP 是有状态协议（跟踪用户目录位置等），HTTP 才是无状态。
  • 控制信息走独立连接 → FTP 属带外传送；控制连接整个会话不断开。
  • 邮件方向：发送全程推（SMTP），读取才是拉（POP3/IMAP）。
  • Web 邮件（如 Gmail 网页版）：浏览器↔服务器两端都用 HTTP，仅服务器之间用 SMTP。
  • 根域名服务器通常不直接给出 IP，只返回下一站顶级域名服务器地址。
  • 完整 DNS 迭代解析最多 8 个 UDP 报文：4 查询 + 4 回答。
  • URL 一般形式 <协议>://<主机>:<端口>/<路径>，请求行里用相对 URL（Host 指明域名）。

📌 关键数字
  • HTTPS = HTTP over TLS，端口 443（课外拓展：SSL/TLS 位于运输层与应用层之间）。
  • IMAP 基于 TCP，熟知端口 143。
  • 根域名服务器全球共 13 个（实为多个冗余服务器组成的集群）。
  • 域名标号 ≤ 63 字符；整个域名（含点）≤ 255 字符。
  • 非持久连接取一个对象 = 2×RTT；流水线方式全部对象连续传输仅 1×RTT。
  • 权限域名服务器：每区建议至少配 2 个。

一分钟自测五问

Q1：主机向本地域名服务器、本地域名服务器向根域名服务器，分别用什么查询方式？

查看答案

主机→本地：一律递归查询（本地替主机跑腿）；本地→根等：通常迭代查询（根只指路，本地自己挨个问）。

Q2：FTP 的控制连接和数据连接各用哪个端口？各自传什么、存活多久？

查看答案

控制连接 21：传命令与响应，整个会话期间保持打开；数据连接 20（主动模式）：传文件内容，每次传输按需建立、传完即关。

Q3：从撰写到读信，邮件协议的"推"与"拉"各发生在哪段？

查看答案

用户代理→发送端服务器、发送端服务器→接收端服务器都用 SMTP（推）；收件人用 POP3/IMAP（拉）从接收端服务器取信。Web 邮件则两端均用 HTTP。

Q4：HTTP/1.0 请求一个文档耗时多少？HTTP/1.1 持久连接的两种方式是什么？

查看答案

HTTP/1.0 非持久：文档传输时间 + 2×RTT（每对象都如此）；HTTP/1.1 持久连接默认启用，分非流水线（等前一响应才发下一请求）与流水线（连续发请求，全部连续传输仅 1×RTT）。

Q5：C/S 模型中客户之间能直接通信吗？P2P 分发文件为何通常更快？

查看答案

不能，客户之间通常不直接通信；P2P 将分发任务分散到多个对等方、支持并行下载，且容量随节点数自然增长，故向多用户分发一个大文件通常比 C/S 快。
